# 第 24 章：用户画像与 Skill 自改进闭环 —— Agent 的"自我成长"

## 24.1 问题：Agent 不了解你，也不会自我反省

两个痛点：

1. **每次对话都是陌生人**：Agent 不知道你喜欢中文还是英文、偏爱什么编码风格、常用什么工具链。每次都要从头沟通。
2. **Skill 只生不养**：进化引擎能自动生成 Skill，但从来不评估 Skill 的质量。低效的 Skill 反复触发，优秀的 Skill 却没有正反馈。

## 24.2 用户画像：USER.md

        let profile = self.get();
        if profile.name.is_none() && profile.coding_style.is_empty() {

## 24.3 Skill 自改进闭环：5 阶段循环

### 架构

```
   ┌──────────┐
   │ 1. 采集   │ ← record_trajectory()（已有）
   │    ↓     │
   │ 2. 评估   │ ← evaluate_skill()
   │    ↓     │
   │ 3. 改进   │ ← suggest_improvements()
   │    ↓     │
   │ 4. 验证   │ ← validate_skill()
   │    ↓     │
   │ 5. 退役   │ ← retire_skill() / unretire_skill()
   └──────────┘
        ↻ 定期运行（run_improvement_cycle）
```

### 阶段 2：评估（evaluate_skill）

4 因素综合评分：

| 因素 | 权重 | 说明 |
|------|------|------|
| **相关率** | 高 | 被加载 vs 实际被使用（低于 30% 扣分） |
| **成功率** | 高 | 被使用时是否帮助完成任务（低于 40% 扣分） |
| **用户评分** | 中 | 用户给出的 good/bad 评分均值 |
| **时效性** | 低 | 版本号 × 使用次数（长期未更新扣分） |

```rust
pub enum SkillGrade {
    Excellent,          // ≥ 0.8：健康，无需操作
    Good,               // ≥ 0.6：可接受
    NeedsImprovement,   // ≥ 0.4：需要改进
    Poor,               // ≥ 0.2：需要大幅修改
    Critical,           // < 0.2：建议退役
    InsufficientData,   // < 3 次加载：数据不足
}

pub enum SuggestedAction {
    None,           // 无需操作
    MinorTweak,     // 微调
    Improve,        // 改进
    MajorRevision,  // 大幅修改
    Retire,         // 退役
}
```

### 阶段 3：改进建议（suggest_improvements）

基于失败轨迹的模式分析：

```rust
pub struct ImprovementSuggestion {
    pub priority: u32,        // 1=低, 2=中, 3=高
    pub category: String,     // "trigger" | "instructions" | "scope" | "tool_usage"
    pub description: String,
}
```

分析维度：
1. **工具使用模式**：失败轨迹中哪些工具出现频率最高
2. **关键词模式**：失败轨迹中用户消息的高频词
3. **触发条件**：相关率低说明触发条件太宽泛
4. **指令质量**：成功率高但相关率低说明指令好但触发太宽

### 阶段 4：验证（validate_skill）

```rust
pub struct ValidationResult {
    pub skill_name: String,
    pub valid: bool,
    pub issues: Vec<ValidationIssue>,
}

pub enum Severity { Error, Warning }
```

检查项：
- 非空
- 至少 1 个 section header（`##`）
- 有触发条件描述
- 有步骤式指令
- 长度合理（5–500 行）

### 阶段 5：退役（retire_skill）

```
Skill 被标记 retired = true
     ↓
Skill 文件末尾追加退役通知
     ↓
下次加载时跳过已退役 Skill
     ↓
手动 unretire_skill() 可恢复
```

## 24.4 思考

**Q: 为什么不直接用 LLM 来评估 Skill 质量？**

A: 成本和延迟。LLM 评估每次调用需要 1-3 秒和几美分。对于数十个 Skill 的定期评估，基于规则的评分更快、更稳定、更可预测。LLM 评估适合"改进建议生成"阶段（需要语义理解），但不适合"是否该退役"这种二元决策。

**Q: USER.md 的隐私问题？**

A: USER.md 存储在用户本地 `~/.baoclaw/` 目录，不上传到任何服务器。用户可以随时手动编辑或删除。Stats 数据仅用于个性化提示词，不用于任何分析或广告。
